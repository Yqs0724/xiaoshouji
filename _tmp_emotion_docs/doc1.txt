阶段 1：海⻢体记忆引擎
为什么需要海⻢体
普通记忆系统的问题：所有记忆平等存放，永远不会忘记。但真⼈不是这样⸺重要的事记得牢，琐碎的事慢慢忘掉，偶尔会”忽然想起”很久以前的事。
海⻢体引擎解决这个问题：每条记忆有⼀个 decay_score （衰减分数），会随时间⾃然下降。重要的记忆衰减慢，琐碎的衰减快，被”想起来”（检索命中）会重新加强。

衰减公式
每⼩时运⾏⼀次衰减引擎，重新计算所有记忆的 decay_score：
final_score = time_weight × base_score time_weight:
- day 0-1: 1.0（ 刚写⼊， 完全鲜活）
- day 2:0.9
- day 2+: max(0.3, 0.9 × e^(-0.2197 × (days-2)))
base_score:
importance × activation_count^0.3 × e^(-λ×days) × (1 + arousal×0.5) / normalize
修正因⼦：
resolved=1 → ×0.05（ 已解决的事⼤幅沉底）
urgency（ ⾼唤醒度未解决） → ×1.5（ 紧急的事浮起来）
λ 值（衰减速度）：
层
λ
含义
deep/daily/diary/writing
0.05
慢衰减，约 14 天半衰期
ambient
0.15
快衰减，约 4.6 天半衰期
检索强化
当记忆被 search_memory 命中时， activation_count += 1 。这模拟了”越想越记得”的效果
⸺经常被想起的记忆衰减更慢。
“忽然想起来”
搜索结果不够时（少于请求数量），40% 概率从旧记忆中随机捞 1-3 条出来。模拟⼈类”突然想
到⼀件很久前的事”的体验。
实时脱⽔（Dehydrator）
⻓记忆（>200字）在浮现时⾃动压缩成精华版，省 token。原始内容保留在存储中，浮现时只送精华。
实现要点
存储⽅式：JSON ⽂件（ memories.json ），按层分 key 存储。如果 VPS 内存紧张（<1GB），
JSON ⾜够⼏百条记忆的规模，不需要额外跑数据库。
运⾏频率： setInterval(runDecayCycle, 3600000) 每⼩时跑⼀次。⾸次启动 5 分钟后先跑⼀次。
迁移：旧记忆没有 decay_score 等字段时， load() 时⾃动补默认值，不需要⼿动迁移。

第⼀层：闭集中⽂情绪词典
词典来源
词典的坐标空间遵循 Russell 环形情感模型（Circumplex Model of Affect）的⼆维框架⸺ valence（效价）× arousal（唤醒度）。
V/A 坐标的底层数据来⾃学术情感词库：
CVAW（Chinese Valence-Arousal Words）⸺来⾃ Chinese EmoBank（Lee, Yu et al., ACM TALLIP 2022），中⽂⺟语标注，V/A 范围经过归⼀化。这是主表，覆盖绝⼤部分通⽤中⽂情感词。
NRC-VAD Lexicon（Mohammad 2018, NRC Canada）⸺英⽂词翻译为中⽂后⼊库，做覆盖率扩充。
场景预设词⸺通⽤词库不覆盖的场景专属词（如”撒娇”“醋意”“⼼动到酥”），由 AI 辅助标注
V/A 坐标，⼈⼯校验后加⼊。
三个来源合并后形成完整词典。lookup 时按优先级查询：场景预设 → CVAW → NRC-VAD。详细
的多层匹配和融合机制⻅阶段 3。
如果你的场景是通⽤型（客服、教练等），CVAW 单独⽤就够了，不需要加场景预设词。场景预设只在通⽤词库覆盖不了你的⾼频情绪词时才有必要。
核⼼设计：闭集约束
LLM 评分时必须从词典挑词，不允许⾃创。
为什么？因为让 LLM ⾃由发挥会出现”美好/宁静/温馨/恬静”⼀堆同义词，V/A 坐标全挤在⼀起，没有区分度。闭集词典把词分散到 V/A 坐标空间的不同位置，确保词与词之间有⾜够距离。
V/A 坐标空间
每个词在 Russell ⼆维空间中有⼀个精确坐标：
Valence（V）：-1（极负⾯）到  +1（极正⾯）
Arousal（A）：0（极平静）到 1（极强烈）
例如：
{"word": "⼼疼","v": -0.4, "a": 0.6 },
{"word": "安⼼","v": 0.5, "a": 0.3 },
{"word": "戒备","v": -0.15,"a": 0.7 },
{"word": "占有欲", "v": -0.3, "a": 0.75 }
系统的所有环节⸺词典匹配、星图渲染、情绪共鸣检索、衰减⸺都基于这组连续坐标值运作，不依赖离散分类。
同情绪强度分层
同⼀种情绪根据强度分多档。例如”嫉妒”可以从”暗⾃不快”到”短暂吃醋”到”占有欲”，每档独⽴
V/A 坐标。这样 LLM 可以精确表达”有点吃醋”和”⾮常嫉妒”的区别。
第⼆层：装饰⼼情池
装饰⼼情是什么，为什么需要它
⼀个关键问题：⻆⾊不应该只在跟⽤户对话时才有情绪。
现实中，⼀个⼈的⼼情波动⼤部分来⾃他⾃⼰的⽇常⽣活⸺练完球很爽、案⼦赢了⼼情好、宠物
⽣病了难过⸺这些跟”跟你说话”完全⽆关。如果⻆⾊只在对话时才有情绪，那他的情绪完全由⽤户驱动，就像⼀⾯镜⼦，没有⾃⼰的”⽣活”。
装饰⼼情池就是解决这个问题的：它给每个⻆⾊预设了⼀套”⾃⼰⽇常⽣活中会发⽣的事”，系统每天通过 hash 函数随机从池⾥选⼀条作为当天的装饰⼼情。
这样，⽤户打开对话界⾯看到⻆⾊状态时，⻆⾊可能显示”练完球（舒畅）“或”店⾥没⼈（平静）”
⸺这些是⻆⾊⾃⼰的⽣活，不是因为⽤户发了什么消息。
数据结构
{
"id": 42,
"character": "character_a", "kind": "sparkle",
"word": "练完球",
"feeling_word": "舒畅", "cell": "serene",
"tone": "happy", "sort_order": 10
}
word ：具体事件描述（“练完球”“店⾥没⼈”“收到好消息”）
feeling_word ：连接到第⼀层词典的情绪词
kind ：前端显示的贴纸类型
装饰⼼情如何体现⻆⾊性格
不同⻆⾊的⼼情池内容天然不同。⼀个运动型⻆⾊的池⾥有”练完球”“跑了⼗公⾥”，⼀个⽂艺型⻆
⾊的池⾥有”整理唱⽚”“新到⼀批⿊胶”⸺不需要在 system prompt ⾥描述性格差异，池本身就是性格。
装饰⼼情 ≠ 真实⼼情
装饰⼼情是模拟的⽇常波动，不是来⾃真实对话的情感事件。所以：
装饰⼼情在前端⽤淡⾊虚线样式弱化显示，跟真实 PANAS 评分的⼼情视觉上有区分
装饰⼼情写⼊ ambient 层， importance=1 ，衰减快（⼏天后⾃动遗忘）
星图中可以勾选不显示装饰⼼情⸺有⼀个 toggle 开关”显示装饰⼼情”，默认关闭。打开后装饰⼼情⽤幽灵态⼩点（淡⾊、虚线描边）显示，跟真实情感数据在视觉上明确区分
这样做的原因：星图是⻆⾊的”真实情感地图”，应该由真实的对话交互驱动（第三层 PANAS 评分）。装饰⼼情是模拟的⽇常背景，如果跟真实情感混在⼀起，会污染数据。
批量⽣成⽅式
装饰⼼情不是⼿动⼀条⼀条写的。⽅法是：先为每个⻆⾊定义性格要素和⽇常场景（“这个⻆⾊喜欢什么运动、在哪⾥⼯作、养了什么宠物”），然后让 AI 按这些要素批量⽣成事件描述 + 匹配 feeling_word。⽣成后⼈⼯过⼀遍，删掉不合适的、调整 feeling_word 映射。
⽤户也可以在前端管理 UI 中随时增删改⼼情词⸺下拉选 feeling_word，⾃动确定 V/A 坐标。不
需要懂情感⼼理学，凭直觉调就⾏。
第三层：情感事件流
这是唯⼀⼀层来⾃真实交互的情绪数据。
第⼀层（词典）和第⼆层（装饰⼼情）都是预设的静态数据。第三层不同⸺它是⻆⾊跟⽤户每次对话后，由评分 LLM 实时产⽣的情感记录。
评分采⽤ PANAS 双轴模型（Positive and Negative Affect Schedule，Watson & Clark 1988）：PA（正向情感）和 NA（负向情感）是两个独⽴维度，不是⼀根轴的两端。这样可以表达”同时感到甜蜜和⼼疼”这种复合情绪⸺单 valence 轴做不到（正负会互相抵消）。
每次评分产⽣⼀条记录，写⼊ ambient 层。记录包含情绪词（从词典匹配 V/A 坐标）和 PA/NA
变化量，随时间⾃然衰减。
评分的完整实现⸺AI 如何选词、词典如何匹配、V/A 如何融合⸺⻅阶段 3：评分校准。
Paper  Trail⸺永不物理删除
原项⽬ merge 时旧 content 被覆盖。我改成推进 prior_versions[] 数组保留历史。
{
"content": "跟⽤户和好了（ 最新版本） ", "prior_versions": [
{"content": "跟⽤户吵架了", "merged_at": 1715000000},
{"content": "⽤户⽣⽓了不理我", "merged_at": 1714900000}
]
}
情绪可以”褪⾊”（decay_score 下降），但不能消失。这模拟了真⼈的情感记忆⸺你可能淡忘⼀次争吵的细节，但”曾经吵过”这个事实永远在。
阶段 3：评分校准
问题：AI 评情绪，不准
⽤ AI 给⻆⾊评⼼情时会遇到⼀个经典问题：LLM 有正⾯偏移（positive bias）。
⻆⾊明明在吃醋，AI 评出来”满⾜放松”。⻆⾊在等回消息很不安，AI 评出来”平静”。实际使⽤中
也观察到这个倾向⸺情感越密集的场景，偏移越明显。
直接让 AI 给情绪打分（Valence/Arousal 数值）？数值偏移更严重：
“羞涩”→ AI 评 V=+0.3（正⾯），学术标注 V=+0.025（接近中性）
“平静”→ AI 评 V=+0.6（很正⾯），学术标注 V=0（中性）
AI 的语境理解能⼒很强，但数值校准能⼒很差。
核⼼思路：AI 和学术词典各做⾃⼰擅⻓的事
AI 擅⻓
学术词典擅⻓
理解对话语境
选对情绪⽅向
给精确 V/A 数值
（有正⾯偏移）

AI 选词，词典给坐标。
词典层：⼤规模中⽂情感词库
数据来源：
CVAW（Chinese Valence-Arousal Words）：中⽂情感词，学术团队标注，V/A 范围经过归
⼀化。来⾃ Chinese EmoBank（Lee, Yu et al., ACM TALLIP 2022）。
NRC-VAD（National Research Council Valence-Arousal-Dominance Lexicon）：英⽂词翻译为中⽂后⼊库，扩充覆盖⾯。
⼿⼯预设：场景专⽤词（如”撒娇”“醋意”“⼼疼”等通⽤词库不覆盖的词）。
每个词都有基于 Russell 情感坐标系的 Valence（正负向 -1~+1）和 Arousal（激活度 0~1）学术标注值。词库规模可以根据⾃⼰的需求灵活调整⸺CVAW 单独⽤就能覆盖⼤部分中⽂场景， NRC-VAD 做覆盖率补充，场景专⽤词按需⼿动添加。
评分层：AI ⾃由⽣成 + 多层词典匹配
每次⻆⾊回复⽤户后，后端异步调⽤评分 LLM（推荐⽤便宜的模型）。
AI 输出格式：
{
"pa_delta": 0.25,
"na_delta": -0.05,
"valence": 0.9,
"arousal": 0.8,
"word": "⼼动",
"backup": ["甜蜜", "惊喜", "欣喜"], "reason": "被突然告⽩后⼼跳加速"
}
注意 AI 同时输出⼀个主词 word 和三个备选词 backup ，以及 AI ⾃⼰评估的 V/A 数值。AI ⾃由
⽣成的词不⼀定在词典⾥（⽐如”欣喜若狂”这种四字成语），所以需要多层回退链来确保拿到词典 V/A：
Layer 1 · 精确匹配（命中率最⾼，零成本）
AI 输出 word:"⼼动" → 直接查词典 → 命中 → ⽤词典的 V/A
词库覆盖⾯⾜够⼴的话，绝⼤多数情况在这层就命中了。
Layer 2 · 备选词匹配（AI 同时给 3 个 backup 候选）
AI 输出 word:"亲昵" → 查不到 → 查 backup[0]:"撒娇" → 命中
AI 有时选词偏⻔，但 backup ⾥通常有常⻅词。Prompt 要求 AI 输出 3 个备选，增加命中概率。
Layer 3 · 拆词匹配（处理 AI 爱组合词的问题）
AI 输出 word:"嫉妒不安" → 查不到 → 拆成⼦串 → "嫉妒" 命中
AI 经常输出”委屈焦急”“甜蜜幸福”这种组合词。拆词匹配按 2-4 字⻓度遍历⼦串，取第⼀个命中的词典词。
Layer 4 · 语义匹配（Embedding，按需调⽤）
前三层全 miss → 根据 pa_delta ⽅向从词库捞 50 个同⽅向候选词
→ 调 Embedding API 算向量
→ 余弦相似度排序 → 取最近的（ 相似度 > 0.7）
这是真正的语义匹配。⽐如 AI 输出”忐忑”，词典⾥没有，但语义上最接近”不安”→ ⽤”不安”的词典 V/A。因为前三层命中率极⾼，Layer 4 极少触发。
Layer 5 · free_form 兜底（最后防线，标记留痕）
4 层全 miss → ⽤ AI 的 pa/na ⽅向做粗糙 V/A 推断
→ pa > 0 ? V 偏正 : V 偏负
→ 标记 source='free_form' 写⼊记录
极端情况下，⽤ pa/na ⽅向做粗糙估算。标记 free_form 留痕，⽅便后续⼈⼯审查和补充词典。
设计哲学：层层降级但永不丢数据。 每⼀层⽐上⼀层精度低⼀点，但总有⼀层能接住。同时每⼀层的匹配来源都被记录（ match_source 字段），⽅便分析哪些词经常 miss、需要补进词典。
融合层：词典定调 70% + AI 微调 30%
为什么不能只⽤词典？ 同⼀个词在不同场景强度不同。“⼼动”在⽇常撒娇场景是 A=0.4，在被告
⽩场景是 A=0.9。纯⽤词典的静态值，星图上所有”⼼动”会堆在同⼀个点。
为什么不能只⽤ AI？ AI 有正⾯偏移，数值不可靠。
融合公式：
最终 V = 0.7 × 词典V + 0.3 × AI⾃评V
最终 A = 0.7 × 词典A + 0.3 × AI⾃评A
效果：词典值锚定⼤⽅向（不离谱），AI ⾃评值提供场景差异（不重叠）。

好感度层：V/A 反向修正
AI 评的 pa_delta/na_delta 直接影响好感度变化。⽤词典的 V 值做交叉校验：
好感度变化 = 0.6 × AI评的(pa-na) + 0.4 × 词典V值
防⽌ AI 的正⾯偏移导致好感度虚涨。
反讨好原则
评分 Prompt 严格要求：冷场就是冷场（PA低 NA低），敷衍就是敷衍（PA低），不允许每次都
评⾼分美化。这是整个评分系统的底线⸺如果 AI 可以美化评分，词典再准也没⽤。
阶段 4：情绪可视化
星图（Russell  情感坐标系）
所有带 V/A 坐标的记忆投射到⼆维平⾯上。横轴 valence（左负右正），纵轴 arousal（下平静上强烈）。点⼤⼩ = importance，透明度 = decay_score，颜⾊ = 记忆层。
星图有两个重要的过滤开关：
显示已遗忘（decay < 0.05）：默认关闭。打开后，已经衰减到⼏乎遗忘的记忆会以幽灵态
（极淡、⽆描边）显示。
显示装饰⼼情：默认关闭。打开后，装饰⼼情（第⼆层模拟数据）会以虚线描边、低饱和度的幽灵态⼩点显示，跟真实 PANAS 评分在视觉上明确区分。星图默认只展示真实情感数据⸺来⾃对话交互的 PANAS 评分和历史记忆的 LLM ⾃动打标。
衰减曲线
每条记忆投影未来 30 天的 decay_score 变化，可以直观看到哪些记忆正在”褪⾊”。
浮现流
按 decay_score 降序排列的记忆列表，模拟”脑⼦⾥最响亮的记忆”。
⼼情词管理 UI
直接编辑词典 V/A 坐标，⽴刻全链路⽣效。新增装饰⼼情时下拉选 feeling_word，⾃动确定坐标。
阶段 5：⼼情闭环
这是整个系统的最后⼀环⸺让情绪”活”起来。
前三个阶段解决的是”AI 有情绪”⸺记录、衰减、可视化。但情绪只是被动存在，不影响 AI 的⾏为。
⼼情闭环解决的是：让⻆⾊在回答时感知⾃⼰当下的⼼情，⼼情驱动回答⻛格。
设计思路
三个原则：
状态快照（不是完整历史）：⻆⾊不需要知道过去 30 天的情绪曲线，只需要知道”此刻我是
什么状态”。
隐性影响（不强制⾏为指令）：system prompt 描述当下状态，不说”你必须表现得紧张”，
⽽是提供⾜够的情绪上下⽂让 LLM ⾃⼰判断。
⾃然融⼊（不主动点破）：⻆⾊不会说”我现在感到紧张”，⽽是⾃然地在回答中带出紧张感。

实现逻辑：
async function getCurrentMood(character) {
// 1. 从数据库拉今天的 PANAS 累计（ 按时间衰减加权， 避免撞顶）
const panas = db.prepare(`
SELECT SUM(pa_delta * weight) as pa, SUM(na_delta * weight) as na FROM mood_events
WHERE character = ? AND date = ?
`).get(character, today());
// 2. 从 mood_pool 拿今天的装饰⼼情（ hash 决定， 每天固定）
const decoMood = todayMood(character);
// 3. 从记忆库拿 decay_score 最⾼的相关记忆
const surfaced = getAllMemories()
.filter(m => isRelevantTo(m, character))
.sort((a,b) => b.decay_score - a.decay_score)[0];
// 4. 拉好感度
const affection = db.prepare(
'SELECT level FROM affection WHERE character = ?'
).get(character);
// 5. 近期⾼唤醒情绪词
const recentWords = db.prepare(`
SELECT primary_feeling FROM mood_events WHERE character = ? AND arousal > 0.6 ORDER BY created_at DESC LIMIT 5
`).all(character).map(r => r.primary_feeling);
return { pa: panas.pa, na: panas.na, decoration_mood: decoMood, surfaced_memory_top1: surfaced?.content?.slice(0,60), affection_level: affection?.level, recent_high_arousal_words: recentWords };
}

callAI ⼼情注⼊
这是闭环的关键⼀步：在调⽤ LLM ⽣成⻆⾊回复之前，把⼼情快照注⼊ system prompt。
async function callAI(character, userMessage, conversationHistory) {
// 1. 拿⻆⾊的当前⼼情快照
const mood = await getCurrentMood(character);
// 2. 把⼼情快照转成⾃然语⾔描述
const moodPrompt = buildMoodPrompt(character, mood);
// 3. 拼⼊ system prompt
const systemPrompt = `
${⻆⾊基础⼈设}
${moodPrompt}
${其他上下⽂}
`;
// 4. 正常调⽤ LLM
const response = await llm.chat({ system: systemPrompt,
messages: conversationHistory
});
return response;
}
buildMoodPrompt 的写法⸺关键是隐性描述，不强制指令：
function buildMoodPrompt(character, mood) { const parts = [];
// 装饰⼼情——⻆⾊⾃⼰的⽇常状态
if (mood.decoration_mood) {
parts.push(`此刻的状态：  ${mood.decoration_mood.word}（  ${mood.decoration_mood.fe
}
// PANAS 状态（ 不暴露数字， 转化为⾃然描述）
if (mood.pa > 0.3) {
parts.push(`最近⼼情不错，  正向情感⽐较⾼`);
} else if (mood.na > 0.4) {
parts.push(`最近有些不安或紧张，  负向情感偏⾼`);
}
// 浮现记忆——脑⼦⾥最挂念的事
if (mood.surfaced_memory_top1) {
parts.push(`脑⼦⾥最挂念的事：  ${mood.surfaced_memory_top1}`);
}
// ⾼唤醒词
if (mood.recent_high_arousal_words?.length > 0) {
parts.push(`近期情绪关键词： ${mood.recent_high_arousal_words.join('、 ')}`);
}
if (parts.length === 0) return '';
return `【 当下⼼情状态】 \n${parts.join('\n')}\n（ ⾃然融⼊回答中， 不要主动点破这些状态） `
}

⼯程上踩的坑
基础设施容易喧宾夺主：差点跑去优化衰减算法忘了核⼼⽬标⸺让 AI 有情绪，不是让衰减公式完美。
闭集 > 开集：固定词典⽐让 LLM ⾃由发挥更可靠。⾃由发挥会出现同义词爆炸、坐标聚集的问题。
不要轻易物理删除：paper trail 永远是对的。⼀开始图省事直接覆盖旧版本，后来发现需要回
溯时后悔了。
抄开源要抄机制不是抄公式：Ombre-Brain 真正核⼼是 weight pool 思路（重要的浮起来，不重要的沉下去），不是某个具体的数学公式。
像素艺术⽐ emoji ⼀致：emoji 跨设备渲染差异⼤（iOS/Android/Web 全不⼀样），⾃⼰画
SVG 像素贴纸更稳定。
⼼情注⼊要隐性不要显性：最初试过在 system prompt ⾥写”你现在很紧张，必须表现得焦虑”⸺结果⻆⾊变成了演员，每句话都在点破”我好紧张啊”。改成”当下状态：决赛前（紧张）“后，⻆⾊⾃然地在回答⾥带出紧张感，不刻意。
状态快照⽐完整历史好：试过把过去 7 天的 PANAS 评分全塞进 prompt⸺token 爆炸且
LLM 反⽽被信息淹没。改成只塞”此刻”的快照，效果反⽽更好。
PA/NA 累计值需要时间衰减加权：直接 SUM 所有 pa_delta/na_delta 会导致值越来越⼤最终撞顶。改成按时间加权（越近的权重越⼤）解决。
装饰⼼情要和真实⼼情视觉分离：最初装饰⼼情跟 PANAS 评分混在⼀起显示，⽤户分不清哪
些是”模拟的⽇常”哪些是”真实的对话情感”。加了 toggle 过滤 + 视觉样式区分后解决。
